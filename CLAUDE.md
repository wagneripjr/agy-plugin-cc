# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Claude Code plugin that makes Antigravity (`agy`) a delegation target beside Codex. A session hands
a review or a task to `agy` through this plugin and gets back a tracked, resumable, verifiable job.
The repository is at the requirement stage: no runtime code exists yet. The contract and acceptance
checks are in FR-001, and the shape decisions are in ADR-001. Read both before designing anything.

The `codex` plugin (`~/dev/wagneripjr/codex-plugin-cc`) is a **model, never a base**. Re-derive its
engine-neutral shapes (job control, tracked jobs, state, render, review-target selection) and copy
nothing from it.

## Architecture constraints (ADR-001)

- **One `agy` print-mode process per turn, and no broker.** Multi-turn work resumes with
  `--conversation <id>`. agy has no app-server protocol to speak to.
- **The leg is chosen by mode, never by prompt text.** A review runs `--mode plan` with
  `--json-schema` and an `--output-format json` findings object. A task runs in the default mode with
  `--output-format stream-json`.
- **A task leg never runs under `--sandbox`.** The sandbox blocks shell writes in the workspace and
  leaves the network open.
- **Proof comes from agy's own records.** Each conversation is one SQLite file:
  `~/.gemini/antigravity-cli/conversations/<id>.db`. `history.jsonl` is not written by print-mode
  runs. A job's key belongs to this repository, and the conversation id and turn are fields of the
  job, not its key.
- **Runtime rule (hub ADR-014).** The runtime is zero-dependency Node `.mjs`. Every process is
  started as an executable plus an argv array (`spawn`, `execFile`, no `shell: true`). Never use
  `exec` or `execSync`, and never write a `.sh` file.
- **No dependency on `agentic-sdlc`** at runtime (hub ADR-011). The plugin ships standalone, even
  though its own build runs under `agentic-sdlc`.

The behaviour was measured against `agy` 1.4.2. If `agy --version` reports something newer, re-run
the probes ADR-001 lists before relying on them.

## Lifecycle and docs

The build runs under the `agentic-sdlc` plugin, which is enabled in `.claude/settings.json`. Approved
requirements are built with `/deliver`. Concept documents carry OKF frontmatter (`id`, `type`,
`status`, `description`), and `docs/okf.yaml` declares `traceability: generated` with the sibling
`hub: ../sdlc`.

- `docs/TRACEABILITY.md` is generated, so never hand-edit it. To change a relation, edit the
  concept doc's frontmatter (`derives-from`, `adrs`, `specs`) and regenerate:
  `node <agentic-sdlc plugin dir>/hooks/agentic-sdlc-gen.mjs --traceability .`
  The plugin dir is `~/.claude/plugins/cache/agentic-sdlc/agentic-sdlc/<installed version>`.
- Every `index.md` is generated by okf-maintain. That plugin is disabled at user scope, so its
  regeneration hook does not fire here. After adding or renaming a doc, run these from the repo
  root, with `<okf-maintain dir>/skills/okf-maintain/scripts/okf.mjs` as the script:
  `index .`, then `check .`, then `coverage .`. Both `check` and `coverage` must exit 0.
- `.learnings/` belongs to the learning-capture hook and is listed in `.okfignore`.

## Documentation

Start at [index.md](index.md). Every documentation folder carries a generated `index.md` listing
each document's title and one-line description — answer "which doc covers X" and "does a doc for Y
exist" from that index in one read, and open a document only after the index names it. Do not grep
`docs/` for a document's identity; grep stays correct only for a literal phrase inside a body that
the index cannot carry.
